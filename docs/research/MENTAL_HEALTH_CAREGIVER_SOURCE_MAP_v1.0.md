# 精神疾病患者家屬支持資源：全台來源盤點與 Agent 自動更新研究
版本：v1.0.0

專案：caregiver-resource-hub  
範圍：研究與文件；未建爬蟲、未部署、未建立排程、未申請服務、未聯絡任何團體。

## 1. 結論與產品方向

**應優先建立「精神疾病家屬可實際使用的活動與支持服務入口」，採官方及承辦團體網站為骨幹、公開活動平台補漏、社群合作投稿補足盲區。Agent 的工作是發現、理解與核對資訊；固定網站下載、日期檢查與去重應由一般程式處理。**

已確認有全國性名錄可持續發現來源，不必只靠搜尋「照顧者活動」：心理健康司的心衛中心通訊錄、康盟團體／友會名錄、社家署協作據點名錄、中央及地方委辦計畫、家總的家照據點。這些入口彼此重疊但不完全相同，應取聯集並保存來源。

「全部挖出來」不能誠實等同全網窮盡：封閉社團、LINE 私群、電話邀請、院內公告及未索引的圖片不在一般公開搜尋覆蓋內。本報告提供全台可擴張的來源網絡和具體種子，並把未驗證項目留成明確待辦。**未宣稱每個網站都已完成 robots、授權、RSS/API 或抓取測試。**

### 服務對象與收錄邊界

- 核心：思覺失調症、雙相／躁鬱症、重鬱等精神疾病經驗者的家屬、手足、伴侶與實際照顧者。
- 不以「已領身障證明」作為網站使用門檻；逐項保留各服務的診斷、證明及轉介要求。
- 優先：家連家課程、家屬支持團體、家屬同儕駐點、照顧者專線、溝通與危機知能、喘息／替代照顧、居住與自立支持、福利與法律諮詢。
- 共融家照據點可納入，但不能因名稱有「家照」就推定接受精神疾病家屬。
- 病友專屬會所、就業服務是相關資源，不自動標成家屬可參加。
- 專業人員積分課、失智專屬活動、一般療癒課另行分類；避免淹沒核心結果。
- 不收錄成員求助全文、病史、留言與參加名單；網站不做診斷或個別治療建議。

## 10. Agent 與一般程式的責任邊界

以下為設計角色，並非本輪已建或啟動的多 Agent 系統。

| 角色 | 輸入→輸出 | 可以做 | 不可以做 |
|---|---|---|---|
| Source Discovery | G01–G12、搜尋→候選來源 | 找新機構、官方外連、縣市缺口 | 自動信任陌生域名／社群帳號 |
| Source Verifier | 候選→source registry | 確認官方身分、分類、可讀性與權限狀態 | 找到即標可爬 |
| Collector（一般程式） | allowlist→變動文件 | 條件請求、限速、分頁、附件 hash | 讓 LLM 每次自由瀏覽全站 |
| Extractor | 有變更的正文／附件→結構資料 | 抽活動對象、費用、場次、申請條件 | 猜名額、時間、疾病資格 |
| Eligibility Reviewer | 原句＋抽取→資格標記 | 分清家屬限定、優先、病友限定、專業限定 | 把一般心理健康課當家屬服務 |
| Reconciler | 多來源活動→同一紀錄／版本 | 比對重複、取消、延期及來源差異 | 靜默覆寫矛盾日期 |
| Publisher（規則） | 已通過資料→網站 | 依門檻刊登／過期／需確認 | 用另一個 LLM 的同意代替原文證據 |
| Monitor | 執行紀錄→例外待辦 | 找停更、版型變、解析異常、來源失聯 | 下載失敗就刪光既有服務 |

工程選型建議：HTTP client＋HTML parser 優先，必要時 browser rendering；PDF 先文字抽取，影像再 OCR；ODS/XLSX 用對應 parser。LLM 僅處理有變更且有歧義的文本。尚未測定各來源格式，不指定已可用的 selector、API endpoint 或 RSS。

## 12. 更新、去重與發佈規則

### 擷取與變動

1. 每站先確認 robots、網站條件與可用授權方式；政府資料開放宣告亦需看實際適用範圍。
2. 清單抓最近頁與未來活動，設頁數上限；保留週期性較深回查，避免只看首頁漏掉置頂／排序異常。
3. 有 ETag／Last-Modified 時使用條件請求；無則比較正文及附件 hash。
4. 限同網域並行與頻率；429 按 Retry-After／退避，403／登入牆列受限，不反覆硬撞。
5. 異常重試後進待辦；服務保留但標「待確認」，不能把故障誤作停辦。
6. 附件換檔、報名頁關閉、日期／名額修改，都產生版本事件。報名頁還存在不等於尚有名額。

### 去重與跨來源核對

- 第一道：canonical URL／主辦者活動 ID／正式報名 URL。
- 第二道：機構＋標題正規化＋場次日期＋地點。
- 第三道：語意相似只產生候選，不單靠相似度自動合併。
- 同一系列不同場次不得合併成一場；不同縣市同名家連家課程不得合併。
- 主辦／承辦原文優先於轉貼，但轉貼若含較新停辦通知，需回查並標矛盾；不是永遠以較舊官網蓋過新公告。
- URL 去掉追蹤參數要小心：event id、reset、分頁與部分站台 returnPageUrl 可能影響可用性。

### 自動刊登門檻

活動至少具備可核實主辦者、標題、明確日期／服務期間、對象、原文與行動入口。未知費用可標未知；日期或對象不明則進待確認，不生成完整「可報名」卡。高風險資格解讀與矛盾內容人工處理。

活動結束後移歷史；長期服務採定期複核而非用活動到期邏輯刪除。建議活動接近舉辦前 7 日及前 1 日回查，服務每月／每季複核；這些是待驗證頻率，未建立排程。

## 13. 近乎全自動的真正瓶頸

1. **發現率**：網站擷取成功率 99% 不代表活動覆蓋 99%；只在 FB／私群公布的部分是未知分母。
2. **即時性**：活動可能已額滿而原頁未改；沒有主辦同步資料就只能標原頁狀態。
3. **資格**：在地、證明、年齡、是否院內個案等條件不能用模型猜。
4. **海報與短連結**：圖片日期、QR code、轉址都需額外處理。短網址解析後仍需來源身分檢查。
5. **維護成本**：不是每縣市一個網站，而是政府、承辦、分站及報名平台多層來源；應按來源家族共用 adapter。
6. **社群合作**：給團體一個「貼公開公告網址或上傳海報」的低負擔入口，通常比維護登入爬蟲更可持續。需實際訪談驗證合作意願，不能假設團體一定願意。

建議最終模式：自動擷取公開允許來源＋組織自願投稿＋少量例外複核。不能承諾完全無人維護，也不能目前就聲稱可達 90% 或 95% 覆蓋。
