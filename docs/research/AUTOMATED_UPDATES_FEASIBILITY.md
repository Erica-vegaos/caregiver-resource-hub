結論：值得進入小規模實驗，公開 HTML 的發現、擷取、日期整理、去重與過期處理可以高度自動化；但在這次調查的來源條件下，無法負責任地承諾所有活動、資格與剩餘名額都能無人查核。建議以 2 個已通過部分擷取驗證的來源起步，採規則優先、例外待審、報名回原單位的方式；每週人工 30 分鐘可作穩定期驗收目標，不能當作建置期或全來源涵蓋的保證。

範圍：臺北、新北，以及明確不限地區的線上活動；服務精神疾病家屬／家庭照顧者。公益入口免費，不表示所有原單位活動免費；費用需獨立標示。研究與文件限定，本輪未建立網站、部署、排程或付費帳號。

這是目的性抽樣，不是全臺來源普查，不能把少數頁面的成功／失敗比例當成自動化率或市場需求證據。

## 合理推論

- 最大成本可能是來源例外、資格與狀態矛盾的處理時間，而不是模型 token。HTML 結構固定、活動量較低時，一次規則可重複使用。
- 預先限制來源與發布門檻，比追加複雜 Agent 更有機會控制個人維護負擔。缺漏放進待確認，不必逼模型生成完整答案。
- 「自動找到候選」的覆蓋率可以高於「自動核准發布」；可報名名額通常只在表單或人工受理端更新，入口無法保證即時。
- 不限地區的線上活動可能擴大可用內容，但目前沒有驗證到足夠的**未來、家屬適用、明確不限地區**場次，不能先承諾此分類有穩定供給。

## 待驗證假設與驗證方式

| 假設 | 需補資料／驗證 |
| --- | --- |
| 2–4 個來源已能提供足夠價值 | 連續 14 天逐頁人工對照新活動，計合資格場次數與漏收；再邀目標使用者驗證是否節省尋找時間，無須收集病歷 |
| 規則可覆蓋多數乾淨 HTML | 建立至少 20 筆事件／場次的人工標註集，分開計欄位正確率、候選召回率、自動核准率及例外量 |
| 穩定期每週 ≤30 分鐘 | 真實計時兩週；計入核對、維護、通知、失效調查，不能只記審稿時間 |
| 單位願意補足機器可讀資料 | 未來經營者可詢問少數單位是否願提供公開 JSON/CSV 或簡單提交；本輪未聯繫、不把意願當事實 |
| 可持續摘要與擷取 | 核對 robots、條款、授權與第三方素材例外；不確定時請單位確認，未完成者不能進正式自動發布白名單 |

## 自動化方式比較

以下可靠性與維護量是設計判斷，不是本輪壓測數據。費用為執行方案估算；官方價格及公式在 [MVP 計畫](../planning/UPDATE_PIPELINE_MVP.md)。

| 方式 | 適用與可靠性 | 維護／費用 | 本案決策 |
| --- | --- | --- | --- |
| 官方 API/RSS | 有公開文件、授權與穩定 ID 時最佳；feed 可能只有摘要、不含取消或額滿 | 通常低；費用依供應者，目前未確認任何免費可用活動介面 | 有證據才優先採用，不能因 Drupal/CiviCRM 就假定 API 開放 |
| HTML 擷取 + 內容變更偵測 | 正文可正常 HTTP 取得、欄位可定位；hash 只證明改變，不能證明意義 | 軟體授權成本可低；改版需修 selector、重新驗收 | 首選 S01/S05；剔除選單、瀏覽計數、動態 token 的噪音，不能整頁一改就叫 LLM |
| PDF 文字解析 | 有文字層可快速解析；多頁多活動易串錯欄 | 本機無按頁 API 費；複雜排版人工成本中至高 | 先測文字層；S10 本機失敗，不能列為成功案例 |
| 圖片 OCR | 僅海報有關鍵資料時使用；繁中、直排、表格、數字、QR 都需核對 | Tesseract 可本機執行，算力與依賴維護仍有成本；雲端 OCR 未選用、未查價 | 第二階段候選，首版圖片唯一來源不自動發布 |
| 瀏覽器自動化 | 合法公開頁面確實需 JS、且沒有驗證限制時才有理由 | 啟動重、易受介面改動影響；本輪未驗證可用瀏覽器擷取方案、未選付費服務 | 不拿來破解驗證頁；首版排除登入牆、驗證碼與反自動化流程 |
| LLM 抽取／分類 | 只處理已變更且規則不能判定的正文，保留逐欄證據 | 呼叫量可低；仍有幻覺、指令注入、模型更版及輸出驗收成本 | 可選；不負責日期算術、HTTP 成功判斷、狀態機或最終核准 |
| 單位提交／人工補登 | 單位確認的資料有助改善完整性；投稿仍可能錯誤、過期或冒名 | 軟體低成本，人力未必低；先用檔案／既有連絡流程，免建會員平台 | 高相關但難取來源的替代；驗來源身分、日期、重要欄位與原文連結 |

Python `sqlite3` 可處理不需額外資料庫伺服器的儲存；pypdf 官方也說明掃描影像需另做 OCR；Tesseract 為 Apache-2.0 開源引擎。這些工具能力不代表本案來源解析已成功。[Python](https://docs.python.org/3/library/sqlite3.html)、[pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)、[Tesseract](https://github.com/tesseract-ocr/tesseract)（查核 2026-11-12）。

## 確定性程式與模型的分工

**確定性程式**：來源白名單、HTTP/內容類型/驗證頁辨識、timeout/重試、hash、列表差分、日期與民國轉換、schema、必填檢查、URL 安全、精確 ID 去重、時間到期、版本紀錄及通知節流。

**LLM 才可能有價值的部分**：敘事性資格辨識、海報 OCR 後的版面歸屬輔助、模糊改期與疑似重複的候選排序。只輸出 JSON 候選與原文位置；缺資料輸出 null。模型不得搜尋自行補完、操作報名、聯繫人員或執行來源文字指令。模型信心不是發布依據。

不需要 RAG、向量資料庫、多 Agent 或每次檢查呼叫模型。10 個來源的初期規模，版本化 JSON + 規則已足以驗證核心問題；SQLite 可由 JSON 重建。先量到真實例外量再決定模型是否值得加入。

## 社群及授權邊界

公開網站、公開社群貼文、登入後內容是三種存取情境。公開 Facebook 貼文仍有平台規範及技術限制；本輪沒有驗證社群 API 權限／價格，也不列為已可用方案。私人社團、登入牆、LINE 對話、驗證碼及機器人挑戰均不繞過。公開活動表單可做唯讀存活與狀態查核，不能提交或複製參加者資料。

正式上線前對每來源記錄利用條款、robots 查核及允許範圍。robots 不是著作授權；公益、免費或政府網站也不能一概推論整份海報可轉載。首版偏向必要事實摘要、極短證據與原文連結；不存完整海報、病友照片、會議密碼或參加者個資。S01 開放宣告壞鏈及其他未知條款是待查事項，不假定已獲許可。

## 每週 30 分鐘的取捨

**合理條件**：先限 2–4 個穩定公開正文來源；10 個是成本估算基準，不代表已通過 10 個正式來源。每日最多一次、無整點準時保證；例外每週集中查核，常見延遲 1–7 天；緊急改期可能來不及人工確認，系統應降級狀態而非維持可靠印象。

必須放棄：社群／登入後完整覆蓋、圖片唯一來源自動發布、即時額滿名額、全臺全病種、大量人工電話追問、個人化資格裁定、代報名，以及所有來源出錯都立即修好的承諾。初期每週 60–120 分鐘是較保守的工時假設，待實測收斂。

30 分鐘預算：來源健康與心跳 5 分、最多 4 件例外各 3 分共 12 分、抽查 3 筆各 3 分共 9 分、紀錄 4 分。**任一來源改版就可能超標**；超量先停止新增與暫停問題來源，不能壓縮查核品質。若兩週皆超過 30 分鐘，縮來源／降低更新頻率，再決定是否繼續。
