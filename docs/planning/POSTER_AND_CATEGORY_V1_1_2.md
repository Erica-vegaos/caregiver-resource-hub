# 頁內海報、分類與核對日期
版本：v1.1.2｜2026-11-14（Asia/Taipei）

## UI
四個主要需求使用4字短標題，數量與截止標籤各自一行。其他活動是程式兜底分類；有符合目前地區／方式的其他場次時才顯示入口卡，進階固定可選，不把所有空類別放滿畫面。
needMatch先判斷既有4類，無法對應才歸other；資料格式、日期與家屬資格檢查仍在前面，other不放行不合資格活動。分類名稱不每日重跑AI生成，亦未啟用每日資料刷新排程。新大類應在確實有內容及需求後擴充規則，不先增設空分類。

## 圖片獲取與顯示
src/media.py從HTML正文候選發現原圖連結、img、data-original／data-src、srcset／data-srcset；排除導覽、頁尾、logo、分享圖示、1px與非允許來源。來源CDN須明列允許host，og:image只低優先候選，不等於海報。
解析器保存原HTML供候選擷取，已支援的兩個HTTP來源在refresh時會列候選；只有正文內alt與活動標題明確相符、且只有一個對應候選時才自動填poster_url。其他情況寫data/review.md，不假裝已完成下載或全文OCR。模組以合成HTML反例驗證，尚未以所有全台來源實測召回率。
本次兩張附圖來自使用者提供的原公告海報副本：陪伴彼此11/15、心光燦爛11/22。逐張比對活動名稱、日期與地點，原始JPEG位元組直接複製，無重繪、壓縮或假稱爬蟲抓到；data/media_registry.json保存來源、capture_method、檔案hash及補充日期。
本地asset僅允許assets/posters下固定格式檔名，build驗hash後套用並複製到dist。媒體登錄在refresh後套用，避免下一次抓取把已補海報覆蓋掉。
其他既有原圖URL改為頁內img，referrerpolicy=no-referrer與延遲載入；顯示失敗不移除活動文字，站內放大dialog可關閉或Esc返回，不要求跳外站。
若來源更換了原海報，舊本地副本仍需有明確更新／撤回流程；不能把保留副本當持續最新保證。現有申訴信箱可要求只移除圖片，原圖與排除紀錄的完整自動清理仍另案。

## 圖片中的新增事實
11/15海報明示費用免費，原文字頁未列費用；media_registry保存原海報fee_fact與來源定位，套用到同活動ID且同原公告URL的資料，新增provided_poster_review證據。文字核對checked_at不因離線build更新；海報observed_at另列，避免假稱再次人工瀏覽原網站。

## 核對日期
卡片改「資料核對 YYYY/MM/DD」。詳情分別列「文字公告核對日期」「海報補充日期」，並說明本站對照來源日期，不代表主辦認證、報名成功或仍有名額。保留實際check_method供內部稽核，不在卡片用模糊「人工核對公告」暗示每次更新都有真人審查。

## 驗證範圍
Python媒體反例：lazy與原圖附件優先、srcset、og:image不當正文、導覽logo追蹤排除、來源限域、相對URL、協定／帳密拒絕、去重與候選上限、本地海報在refresh後補回且來源需一致、免費有圖像證據。Node新增other不漏接也不吞既有分類。
UI驗證應覆蓋320／390px、截止標籤分行、免費、兩張本地img實際載入、站內放大／關閉、壞圖降級與分類切換。公開部署使用分支預覽驗證後再合併。
