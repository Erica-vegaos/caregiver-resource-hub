# 有伴維護與發布 v1.0.0

日期：2026-11-14（Asia/Taipei）。第一版為可部署、可手動刷新之全台活動搜尋；不是已完成全台資料覆蓋或全自動營運。

## 一次更新

執行 `python src/build.py --refresh`，再讀取 `data/review.md`。現有解析器只接受已支援模板，新來源與不明資格不直接變成已核實活動。也可在 GitHub Actions 手動執行「Refresh and review activity data」，下載產出的資料與預覽；該流程不會自行改寫 main 或發布網站。

人工核對活動新增到 `data/national_records.json`。確認家屬資格、實際場次日期、原單位網址、報名狀態；不明費用用 null、不明名額用 unknown，核對日期只能在讀取原公告後更新。保留必要事實與短證據，不複製公告全文。

執行 `python -m unittest discover -s tests -v`、`node --test tests/test_search.cjs`，再用 `python src/build.py` 產出單檔 `dist/index.html`。檢查手機搜尋、活動詳情與原公告連結，才發布對應的來源版本。

## 異常處理

- 來源失敗保留上次成功資料並標記，不推定活動取消。
- 資格、日期或證據不足的候選放待審，不用補猜欄位讓它通過。
- 每週檢視未來活動的待確認項目與來源失敗，長期無資料的縣市維持收錄不足提示。
- 同一場出現在多處公告時，去重以場次為單位，系列不同日期不能合併。
- 「原文接受報名」不代表仍有名額，「報名截止」與「活動結束」分別處理。

## 持續自動營運的剩餘工作

本版沒有啟用定時排程；私人的網站預覽是靜態發布，不會在背景自行抓取。全自動更新仍需將「定時執行→通過資料與搜尋測試→核准可信模板→發布→失敗通知」串接到固定執行環境，並累積連續運行紀錄。現有 GitHub 手動更新流程是可驗證的起點，不能宣稱已完成近乎全自動營運。

新增來源先保持人工模式，待有真實標註與多次成功擷取紀錄，再逐一升級自動刊登。目標是降低人工維護量，不是每次讓模型重新猜所有公告。
