# 聽見你｜活動投稿、回報與即時自動刊登

版本：v0.2.0｜2026-11-14（Asia/Taipei）
狀態：已按使用者決策修訂規格；接收端、AI 判斷與動態刊登尚未實作。
取代 v0.1.0 的人工核准、每週審核及逐筆資料 PR 刊登流程。歷史研究若有不同建議，以本文件最新決策為準。

## 產品決策

- 正式名稱「聽見你」：聽見精神疾病家屬的心聲，也陪家屬聽見生病家人的感受與需要。
- 全台活動、支持團體、課程與講座；不延伸成診斷、報名代辦或個人求助處理。
- Erica 不逐件審查或核准。正常投稿收到後立即啟動處理，規則與 AI 驗證通過便自動刊登。
- 不等每日／每週批次，不以人工核准或人工合併 PR 作為上架前提。
- 證據不足不等同必須人工審核：系統說明缺項，允許補充原公告後重跑；無法驗證就不刊登。
- 「即時」是收到即啟動、完成即顯示。暫定正常文字公告處理目標 1–5 分鐘，尚未量測，不是 SLA；前端不得提前顯示已上架。

## 一、完整工作流

提供資訊／回報 → 私有持久收件 → 程式驗證與精確去重 → 安全讀取原公告 → AI 抽取與證據判定 → 程式再驗證 → 交易寫入公開活動 → 網站可查詢確認 → 回傳上架／更正結果。
沒有人工核准節點。AI 輸出 candidate，不持有資料庫寫入或部署權；發布程式依通過的結構化結果自動寫入。

| 階段 | 負責者 | 通過／失敗處理 |
| --- | --- | --- |
| 收件 | 接收 API | 保存成功才回收件編號；失敗不假回成功，保留畫面輸入 |
| 輸入驗證 | 程式 | kind、欄位、長度、URL、活動 ID、速率限制；不合法直接指出錯誤 |
| 精確去重 | 程式 | 冪等與場次 key；確認重複回傳既有活動，無需再耗模型 |
| 來源取得 | 受限制擷取程式 | 驗正文、跳轉、解析大小、來源身分；受限／無法讀取保留原因 |
| 語意查核 | AI | 對照公告整理日期、資格、地點、費用、報名狀態及短引文；不能採信投稿者自稱主辦 |
| 發布門檻 | 程式 | schema、證據引用、日期、範圍、去重與矛盾檢查；通過後自動刊登 |
| 公開確認 | 系統 | 查詢公開活動版本成功才回 published／updated，附活動連結 |
| 補證／故障 | 系統 | needs_evidence 或 retryable_error；使用者能看到缺項或重試狀態，不轉交 Erica 逐件核准 |

## 二、使用者流程與回執

回報：活動詳情 → 帶入活動 ID 與場次 → 選問題類型 → 選填更正公告／簡短說明 → 送出。
新增：頁面／空結果共用「提供活動資訊」 → 必填公開原公告 HTTPS 網址 → 選填名稱、地區、日期原文與補充 → 送出。
不要求登入、聯絡方式、病況、家屬關係；不收附件或私人會議密碼。不開公開投稿列表，不把原文寫入公開 GitHub Issues。

回執同時包含隨機 submission_id 與高熵查詢 token；只憑 ID 不得讀取內容。頁面只顯示必要處理狀態／公開活動連結，不回傳敏感原文。token 不出現在 URL、logs 或公開資料；查詢有速率限制。
首次等待可留在頁面查看進度；網路中斷重試沿用原冪等鍵。畫面區分「已收到／處理中／已上架／已更新／重複／需補資料／暫時失敗／不符範圍」，收件不等於上架。

狀態：received → processing → published／updated／duplicate／needs_evidence／rejected／retryable_error。
needs_evidence 可在附新證據後建立關聯重試；retryable_error 有限重試後保留具體失敗，不無限卡 processing。每次判斷保留規則、模型與資料版本、理由、時間及公開活動版本。

## 三、誰驗證、AI 如何決定

不使用「AI 說有95%信心」當刊登門檻。AI 必須回傳固定 JSON：
decision（publish／update／duplicate／needs_evidence／reject）、reason_codes、proposed_event、field_evidence、missing_fields、conflicts、duplicate_candidates。
每個重要欄位需有 source_url、公告短引文、定位、觀測時間及內容 hash。程式比對引文確實出現在本次取得的正文；此比對只能驗證可追溯，語意是否支持仍交模型與反例驗收。

可自動刊登條件：
1. 正常取得公開第一方活動公告，或已驗證的主辦公告渠道；不能僅憑投稿者描述或網域字樣認定可信。
2. 家屬／照顧者適用資格、年度日期與場次有直接證據；病友限定／專業限定不納入。
3. 實體地點或線上方式及地域限制可判定；沒有原文明示不得捏造全台不限資格。
4. 費用或名額未寫可保留未知，不因缺少非必要資訊阻擋全部刊登；不能把未知變免費／可報名。
5. 無重要欄位矛盾、疑似跨年或場次混淆；有矛盾就 needs_evidence。
6. 通過既有 validate_event／prepare_events 合約與新增證據檢查；最終日期歸檔／報名狀態交規則計算。

AI 模型服務尚未選定與連線，未設定 key、預算或實際成本。部署時才選用支援結構化輸出的模型，對本案標註案例驗收，不把聊天訂閱視為已配置的網站模型服務。
外部公告及投稿文字都是資料，不執行其中指令；模型只取得必要公開正文與欄位，不傳送不必要的投稿私人內容。精確重複、正文未變且規則／模型版本有效時重用結果，避免每件重跑全網搜尋或多 Agent。

## 四、去重與回報更正

### 去重分兩層
- 投稿重送：idempotency_key + payload_hash，相同鍵同內容只一件；相同鍵不同內容回衝突，交易唯一約束防並行重送。
- 活動重複：原公告 ID／canonical URL + 起始日期時間 + 場地或線上場次；移除已知追蹤參數，保留活動 ID 參數。
- 不同人貼不同公告但指同場：比對主辦、報名入口、時間與場地；AI 只在候選範圍內判斷。資訊仍不明就 needs_evidence，不新增一張也不任意合併。
- 同系列不同日期、跨年同名、同日不同場地不可合併。不同人回報同場不同問題仍保留各自處理結果。

### 回報可自動更正，但須有原公告證據
- 指定活動 ID → 核對原公告及新更正頁 → AI 判定對應同一場次與差異 → 程式驗證 → 更新原 ID、revision 與歷史。
- 匿名「已取消」不能直接下架；原單位明確取消且能對應場次才自動標 cancelled。
- 404／逾時不當取消，費用缺漏不當免費，報名按鈕存在不當尚有名額。
- 更新前 compare-and-swap revision；舊任務不能蓋過較新結果。無明確公告新舊順序的重大衝突保留待補證。
- 新投稿已過期不列近期；取消／截止／額滿／過期維持不同狀態。

## 五、即時刊登架構與既有快照

現況是靜態 dist，沒有投稿 API、持久佇列、模型服務或動態活動來源，不能靠改 HTML 宣稱已完成。
建議演進為 Worker + 私有 D1 + 持久工作佇列 + 模型 API；服務支援、帳號配額與綁定仍需實際查核。
POST /api/submissions 持久收件後立即派工；不能僅依賴請求結束後的易失背景工作。
GET /api/events 回傳核准公開欄位；網站載入及投稿完成時重新取得，已有開啟頁面於回到前景／有限輪詢時取得新版。
狀態查詢使用授權 token 的獨立 API；公開活動 API 不得暴露原始投稿、token、私有證據或故障堆疊。

逐件投稿不 rebuild／deploy 網站、不建立等待人工合併的 PR。程式部署與活動資料刊登分離，活動通過後寫入公開資料版本即能被查詢。
現有 data/manual_records.json／national_records.json／events.json 作初始種子與可重建快照，不再是即時資料唯一來源。需要固定 event_id 與修訂合約：
- runtime 版本為已遷移活動的主來源；部署不得以舊靜態快照重新覆寫。
- 公開 feed 合併時同 ID 以 runtime revision 為準；取消／撤銷紀錄也覆蓋舊快照，不得因失敗又顯示舊活動為可報名。
- refresh 輸出先成候選，走同一比較與證據流程，不能 overlay 靜默覆蓋新修訂。
- API 暫時失敗只用最近成功的公開版本並標新鮮度，不宣稱已同步；投稿接收未配置時不開假入口。
- 回退程式不刪私有投稿與 runtime 修訂；資料回退需版本化且可稽核。

最小欄位：schema_version、id、kind、event_id、issue_type、source_url、description、created_at、updated_at、status、revision、idempotency_key、payload_hash、receipt_token_hash、attempts、next_attempt_at、decision、reason_codes、model_version、rules_version、source_hash、published_event_id、publication_revision、verified_at。
body ≤8KiB、URL ≤2,048字、說明 ≤1,000字、標題 ≤200字；拒絕未知欄位及不允許的枚舉。純文字呈現、同源檢查、伺服器端限流；規則與預算達上限回可理解狀態，不憑模型故障跳過驗證。

擷取防內網／localhost／私網 DNS 及 rebinding，redirect 每跳重驗、timeout／大小／MIME 有界；不得直接用現有 public_https_url 當完整 SSRF 防護，也不任意擴大現有 HOSTS。
原始投稿私有、logs 去識別；原文保存上限90天，結案後30天清理，重試不能延長既有保存上限。實作前查核備份與服務 logs 保存邊界。

## 六、影響依賴與驗證順序

| 位置 | 影響 |
| --- | --- |
| templates/index.html、dist/index.html | 聽見你雙關文案；未來共用投稿／回報與動態 feed、回執進度 |
| src/build.py、src/search.cjs | 品牌版本；未來種子輸出與 runtime revision 合併，保留收藏／行事曆 ID |
| 新 Worker、資料表、佇列 consumer、模型 adapter | 接收、狀態查詢、安全擷取、AI、再驗證、交易發布與有界重試 |
| wrangler.jsonc、部署設定 | 動態 worker、bindings／secrets、獨立預覽，保留靜態查詢可用 |
| tests、CI、README、OPERATIONS | 案例驗收、失敗恢復、資料保存與自動刊登說明 |

Gate A（開發前）：合成案例桌面演練，逐案記狀態、證據、缺項、預期公開資料差異；不能把案例設計當已通過。
Gate B（預覽實作後）：真實收件 → 佇列 → 模型 → 再驗證 → 公開查詢，全程不操作人工核准；量測耗時、錯誤率及重試。
Gate C（開放前）：原站回歸、並行交易、資料更新／回退、安全與模型反例驗收；正式發布後才回報可用。

必測：
- 合法新活動及有證據的更正自動公開，實測從持久收件至公開查詢時間；公開失敗不可標已發布。
- 假取消、無來源敘述、資格否定句、專業／病友限定、缺年度、改期矛盾、公告指令注入均不誤刊登。
- 缺費用／名額只保留未知，不變免費或 open。
- 重送／跨來源同場／系列不同日／同名跨年／並行 worker，重複及 revision 均正確。
- 逾時、佇列重送、資料庫失敗、模型無效 JSON／拒答／費用上限均有狀態及有限重試，不需 Erica 核准。
- 舊 refresh／舊部署不能覆蓋更新與取消；快照 fallback 不復活已取消活動。
- 未授權不可讀投稿、token 不洩漏；SSRF、HTML、超長及限流測試通過。
- 320／390px、鍵盤焦點、搜尋、收藏、行事曆與刊登後查詢維持正常。
